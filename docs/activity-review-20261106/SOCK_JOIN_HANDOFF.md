# 袜踝台阶与色调跳变：同源纹理/连续踝部方案

2026-11-07。已核对膝修形回交、A/B 数据与当前 builder。膝局部修形已合入且主要回归指标成立，继续保留。此单只处理剩余袜踝问题。

## 结果

隔离原型已消除同姿态换附件时的袜筒台阶和鞋面色调跳变：只换 normal/heel 附件名、骨骼姿态完全相同时，三帧全图像素差 `[0,0,0]`。

本次没有生成新图、没有修改任何源 PNG，也没有覆盖动画侧 builder 或正式游戏。原型脚本 `tools/probe_activity_sock_join.py`，输出到 `tools/_debug/activity_sock_join_spine/`，基于动画侧已经合入膝修形的当前导出，不再叠加第二套膝修形。

## 原因与处理方式

此前普通鞋来自 v1、提踵鞋来自 v2，两者的袜筒宽度、切口描边、鞋面色调与高光不是同一份像素。只裁窄 alpha 会丢掉一部分侧边描线；额外补短袜片又会在交接处留下横向台阶。脚尖固定只能保证接地，不会消除材质切换差异。

本方案使用**同一份原画 + 连续踝部蒙皮**表现当前正面的小幅提踵：

1. `leg_heel_l/r` 复用 `leg_l/r` 的正常纹理和网格，取消本方案中的袜筒 row270–300 裁窄/截短。原 normal 腿图不修改。
2. shoe slot 仍然独立，普通鞋/提踵鞋附件名称仍保留，原时间线可继续切换。但两种附件都使用普通鞋的原始纹理，并由相同的踝部加权网格驱动，不再在显示时切入 v2 不同颜色/朝向的鞋图。
3. 小腿/鞋重叠区用**同一个世界坐标权重函数**：源画布 y≤858 为 calf，y≥895 为 foot，中间 smoothstep 过渡。腿网格的重叠末端与鞋网格使用相同权重，保证同一原画像素不会一部分跟 calf、一部分跟 foot 而分开。
4. hip+5、foot−5 和已经确认的接地参数不变；上方踝/袜随小腿抬起，鞋尖与鞋底下缘跟固定 foot。抬跟意图通过连续形变表现，不靠突然换一张不同鞋。
5. 保留膝修形的现有权重和轨道；新增踝部权重只影响远低于膝的区域，不把已经收敛的膝问题重新打开。

这属于现有 Spine/生成管线中的几何与纹理复用修复，因此无需再次调用绘图生成。同源纹理避免了新补画再次引入色差。适用范围仍是当前正面、5源单位的小幅动作；不宣称支持侧面大幅踮脚。

## 给动画侧的合入说明

- 建议单独加 `--ankle-continuous` 或同义明确开关。保留原 --heel-v2 路径作为回退，不覆盖 v1/v2 包和 manifest，不把本方案冒充成只换 v2 PNG。
- 参照脚本 build 的三段：为 leg mesh 踝末端增加 calf↔foot 权重；用普通鞋 region 的原注册位置创建加权鞋 mesh；normal/heel 各自复用同一原画纹理/网格。
- mesh 纹理名要与 atlas 一致。原型为 `shoe_l`、`heel_l` 等保留同名 atlas 别名，避免没有 mesh.path 时误读到旧 extra/heel_l 图。两个别名是相同原画，尺寸均沿用普通鞋82×230，局部注册取普通鞋原 region；不要混用旧 v2 的69×80 region值。
- 腿、鞋 slot 继续独立，不能把整腿母件再叠挂出来，也不需要删除已有动作时间线。A 套验证后可再清理无意义的同像素换图；本次先保持调用兼容。
- 不要直接复制 debug skeleton 为正式版本，按当前 builder 的骨索引与 atlas 管线合入。原型包含用于证明同姿态无跳变的 `activity_sock_switch_probe`，无需进正式角色包。

## 后续验收边界

此项已在隔离原型解决，可以交动画侧合入。合入后回归招手、踏步、提踵，以及同一个 animation state 的 march→heel→relax；不能只在每帧 reset setup 的取样里推断切状态后控制骨必定清零。原型验证不是正式游戏集成验收。
