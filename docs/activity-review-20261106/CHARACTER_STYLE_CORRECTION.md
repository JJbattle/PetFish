# 活动造型偏离日常角色：根因与修复边界

2026-11-08。用户提供日常站姿与活动招手截图，指出两者样式差距明显。本次核对正式角色原画、活动拆件与运行缩放代码。

## 结论

**主要是活动美术补画/拆件注册偏离了原角色；接入的缩放策略另有次要问题。** 不能把差异归因于招手动作，也不能要求动画侧继续用骨骼掩饰不同脸型/发型。

- 正式站姿构建器 `tools/build_spine.py` 以 `assets/art/pet_portrait.png` 为源，现有角色表情、头发、服装与尾巴属于这套基线。
- 活动包 `activity_spine_kit_v1` 从再次生成的分镜补绘头、后发、身体、四肢和尾巴；尤其 common 的参考来自坐姿分镜，不是直接从正式原画提取。新头脸/眼睛、发束体积/卷曲、身体和裙摆比例、尾鳍形状都变化了。
- `prepare_activity_kit.py` 对这些独立生成的头/后发/身体/腿分别按450/630/330/230等目标高度重新注册，只保证能拼起来，没有把原画关键点与头身比例锁定。静态试装已存在造型偏差。
- 当前 `pet.gd` 将 activity 与正式 standing 都传入同一个 target_h，再分别除以848/820的整身包围盒高度。坐/趴已有头高对齐规则，activity没有对应处理。整身等高不会自动保证头高、脸大小、裙长和腿长一致。

此前我们连续检查关节、膝切边、鞋袜接缝，却没有先做“原角色→活动中立→原角色”的角色一致性验收。这是美术交付与审核顺序的问题。技术探针/像素闭环通过，不等于用户看到的是同一只大肥鱼。

## 立即调整工作顺序

1. 当前活动 v1 只能作为技术动作样机，不作为最终角色美术通过。A套计时/提醒/动作逻辑可以保留；不要继续以这套外形扩B/C或坐姿来固化偏差。
2. 以正式 `pet_portrait.png` 和现有生产站姿拆件为唯一身份母版。优先复用现有脸、眼睛、头饰、刘海/后发、躯干/围裙和尾巴，**不要把生成分镜中的新脸再当作角色母版**。

   已核对生产站姿骨架含60根骨骼、51个slot，已有头脸/眼嘴、左右发束、身体、裙摆、腿脚、上下臂与手。因此站立跟练优先直接在现有生产站姿骨架的隔离副本新增动作，而不是重新组一只活动专用角色。仅对实际缺少的关节底图/姿态补图。
3. 新动作真正缺的手臂姿态、裙下遮挡、屈膝等局部由美术补；图像编辑要锁定原脸/原发型/原服装的像素和比例，只修改必要区域。现有活动膝/袖子/踝部的绑定经验可迁移，不能把不同角色外形一并迁移。
4. 先做一个匹配日常角色的活动中立姿势，再做同母版的招手目标帧，二者都与正式站姿在同一画布、同一地面、相同头高下对照。先比较脸、发型、裙摆、尾鳍和头身比，再比较关节。
5. 尺度对齐沿用 `docs/POSE_HEAD_SCALE.md`：头饰上缘到下巴的基准头高，忽略呆毛、长发、道具；整体等比缩放一次，保持脚底锚点。不能靠分别拉头、压身、缩腿来掩饰不同原画。
6. 中立/招手造型一致后，再用原活动时序接入并回归动态、裁切并集与点击区域。当前不改喝水第4版长袖、提醒/菜单分工，也不清除已完成的逻辑与验证工具。

## 分工

- 美术侧负责回到原画母版、复用/补齐必要局部、交付中立与招手对照及精确装配；本次新脸/新后发/新尾巴的偏差不归咎于动画制作者。
- 动画侧保留现有活动逻辑与可用的绑定算法，确认新包后迁移，不先对现有偏差素材做更多比例补丁。
- 本次只完成原因核对与纠偏任务定义，**尚未交付替换后的角色素材，也没有宣称外形已修复**。需要替换的当前显示仍是原样，不能拿本文当修复结果。
